# Matriz de Seguridad, Privacidad Biométrica (Ley 1581) y Mitigación OWASP Top 10:2025

- **Microservicio:** `PT8080-VirtualTryOn-Service` (`ms-probador-virtual` · Puerto `8500`)
- **Squad:** Portal8080 (`PT8080`)
- **Requerimientos Cubiertos:** `SR-RF-23`, `SR-RF-24`, `SR-RF-25`, `SR-RF-26`, `SR-RF-27`, `SR-RNF-02` (Habeas Data / Ley 1581 de 2012)

---

## 1. Resumen Ejecutivo de Seguridad

El microservicio de Probador Virtual procesa datos sensibles (fotografías corporales frontales de los compradores), por lo que aplica **Defensa en Profundidad** desde la capa de entrada REST hasta el almacenamiento en Azure Blob Storage y PostgreSQL (`probador_db_qa` / `probador_db_prod`):

1. **Autenticación y Autorización Stateless Bearer JWT** con verificación estricta de titularidad del recurso (`userId` del token vs. `userId` del recurso).
2. **Principio de Mínimo Privilegio en Almacenamiento Binario:** Las URLs SAS expuestas al cliente o persistidas se sanitizan mediante `AzureBlobStorageAdapter.sanitizeToReadOnlySasToken(...)` y son validadas por el Value Object `SasSignedUrl` para garantizar exclusivamente permiso de lectura (`sp=r`), alcance de blob (`sr=b`) y protocolo HTTPS (`spr=https`).
3. **Cero Secretos Quemados en Código:** Todas las credenciales (`JWT_SECRET_BASE64`, `AZURE_STORAGE_BASE_URL`, `AZURE_SAS_TOKEN`, `DB_URL`, `DB_PASSWORD`, `FASHN_API_KEY`) se inyectan exclusivamente desde variables de entorno y **GitHub Secrets**.
4. **Cumplimiento de la Ley 1581 de 2012 (Habeas Data / Derecho al Olvido):** Ninguna fotografía se almacena ni procesa sin consentimiento biométrico vigente (`BiometricConsentValidator`), y el titular puede ejecutar la purga física definitiva (`DELETE /api/v1/try-on/personal-photos/{jobId}` o vía evento `user.account.deleted`).
